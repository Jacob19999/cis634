# Semantic Retrieval of Aviation Safety Reports with Frozen Sentence Embeddings

CIS 634 (NLP) class project by Jacob Tang and Aarambh Shrestha.

**Question.** Can a frozen sentence embedding retrieve NASA ASRS reports that describe
the same operational issue when the wording differs? Does that ranking fail under
negation, altitude/number changes, direction, or event order?

`asrsbench` is a single pipeline that runs any number of retrieval systems (BM25, any
sentence-transformers model, and hybrids of them) on the same corpus and evaluation
tracks. To add a model, add a few lines to a YAML config.

**New here?** The [tutorial](TUTORIAL.md) walks through installing, searching the corpus,
running a benchmark, reading its results and benchmarking your own model.

```
Research/                     proposal, class guidelines
configs/                      benchmark configs (milestone.yaml, smoke.yaml, extended.yaml)
data/queries/                 topical query set + silver relevance rules (committed)
data/contrast/                meaning-change test set (committed)
data/qrels/                   human relevance labels and judging pools (committed)
data/processed/               cleaned corpus + chunks (generated, git-ignored)
src/asrsbench/                pipeline code
results/<run>/                metrics tables and summary.md per run (committed)
tests/                        unit tests (pytest)
```

## Pipeline

```bash
asrsbench prepare                      # download + clean + chunk  -> data/processed/
asrsbench run configs/smoke.yaml       # ~ minutes; end-to-end check
asrsbench run configs/milestone.yaml   # BM25, MiniLM, E5, hybrids on all tracks
asrsbench search configs/milestone.yaml e5-small "crew descended to the altitude meant for another aircraft"
asrsbench pool results/milestone       # blind judging pools for the two annotators
asrsbench labels data/qrels/pool_v1/pool_A.csv data/qrels/pool_v1/pool_B.csv  # -> qrels + kappa
pytest                                 # unit tests
```

Unit embeddings are cached in `cache/embeddings/`, so re-running a config only encodes the queries.

### 1. Data preparation (`src/asrsbench/data.py`)

Source: [`elihoole/asrs-aviation-reports`](https://huggingface.co/datasets/elihoole/asrs-aviation-reports)
(Apache-2.0). It has 47,723 de-identified ASRS reports from Jan 2012 to Mar 2022, split into 38,655 train, 4,295 validation and 4,773 test.

| Step | What and why |
|---|---|
| Field selection | We keep the reporter narratives (1 or 2 per record; 23.5% have a second reporter), the analyst synopsis, and the analyst codes (anomaly, human factors, communication breakdown, flight phase, result, detector, primary problem). Only the narratives are searched. |
| Comma repair | The ASRS export turned every comma into a semicolon: `10;000 FT`, `IAF; we set`. We restore the commas in the free text so numbers and clauses read as normal English. The coded fields keep `;` as their list separator. |
| Incident grouping | Union-find over shared accession numbers and identical narratives. This gives 47,687 incident groups: 70 reports belong to multi-report groups, and 13 of those groups cross the official splits. Retrieving a sibling report counts as correct, and any fine-tuning (Extension D) must split by group. |
| Placeholder removal | 2,906 second narratives (26% of them) are editorial notes such as "[Report narrative contained no additional information.]". These are dropped. In v1 they were indexed, and dense models matched generic queries to them. |
| Chunking | The narratives have no paragraph breaks, so "paragraphs" are sentence-aligned windows of at most 150 words with a 1-sentence overlap. A leftover tail under 40 words is merged into the previous window. This gives 136,842 chunks (2.9 per report), and only 0.9% are under 30 words (3.7% in v1). A chunk averages 150 word-piece tokens (99th percentile 222), so it fits MiniLM's 256-token limit; 0.02% are truncated. |
| Focus subset | 21,183 reports coded as altitude, clearance, track/heading or communication-breakdown events are flagged as the proposal's focus area. |

Corpus statistics: `data/processed/stats.json` (regenerated by `prepare`).

### 2. Retrieval systems (`src/asrsbench/retrievers/`)

Every system scores *units*. A unit is either a chunk (`doc_mode: chunk_max`) or a whole narrative (`doc_mode: whole`). A report's score is the maximum over its units (MaxP), and the best unit is returned as the matched passage.

| type | implementation |
|---|---|
| `bm25` | Okapi BM25 (k1 = 1.2, b = 0.75, Lucene IDF) on sparse matrices. Tokens are lowercased, stopwords removed, and words reduced to their stem (Snowball). Scores are tested to match the `bm25s` library. `stopwords: english_keep_negation` keeps "not", "no", "never" and similar words. |
| `dense` | Any sentence-transformers checkpoint, with optional query/passage prefixes (E5: `query: ` / `passage: `). Embeddings are cosine-normalised. Search is exact (every chunk is scored). |
| `hybrid` | Reciprocal rank fusion (k = 60) or a weighted sum of min-max normalised scores, over any systems defined earlier in the config. |

### 3. Evaluation tracks (`src/asrsbench/tracks.py`)

| Track | Queries | Relevance | Metrics |
|---|---|---|---|
| `synopsis` | NASA analyst synopses of 1,000 validation-split reports. Analysts write it after reading the narrative, in shorter, different words, though about half its content words also occur in the narrative. | The summarised report, plus any other report of the same incident | MRR@10, R@1/10/100 |
| `topical` | 40 analyst-style issue descriptions (`data/queries/topical_v1.yaml`), split into 20 dev and 20 test | Grades 2/1/0. *Silver* labels are derived from analyst codes and, for 24 queries, synopsis keywords (rule per query); *human* labels come from blind pooled judging | nDCG@10, P@10 (grade 2), P@10 lenient (grade ≥ 1), MRR@10 |
| `contrast` | 100 items: 25 each of negation, numbers (altitude/speed), direction, and event order (`data/contrast/contrast_v1.jsonl`) | An item passes if sim(original, paraphrase) > sim(original, changed) | accuracy per category (chance = 0.5) |

95% bootstrap confidence intervals are attached to every mean. A paired randomization test compares each pair of systems on the primary metric of each track.

## Adding a model

```yaml
# configs/my_run.yaml
systems:
  - name: bge-small
    type: dense
    params: {model: BAAI/bge-small-en-v1.5,
             query_prefix: "Represent this sentence for searching relevant passages: "}
```

Then run `asrsbench run configs/my_run.yaml`. Results are written to `results/my_run/`.

## Results (Phase 2 milestone)

Full tables with 95% CIs: [results/milestone/summary.md](results/milestone/summary.md). The write-up is in [reports/milestone/phase 2 jacob tang Aarambh.pdf](reports/milestone/phase%202%20jacob%20tang%20Aarambh.pdf).

| System | Synopsis MRR@10 | Synopsis R@100 | Topical nDCG@10 (silver) | Contrast, overlap-controlled |
|---|---|---|---|---|
| BM25 | **0.425** | 0.753 | 0.630 | 0.53 |
| MiniLM | 0.268 | 0.648 | 0.591 | 0.70 |
| E5-small | 0.241 | 0.607 | 0.438 | **0.85** |
| BM25 + E5 (RRF) | 0.378 | 0.759 | 0.633 | – |
| BM25 + MiniLM (RRF) | 0.380 | **0.786** | **0.706** | – |

Early findings:
- **BM25 is the strongest single system on synopsis queries**, which is the opposite of what we expected. Its lead holds on synopses that share no identifiers with their narrative. On topical queries BM25 and MiniLM are not significantly different (p = 0.29).
- **Fusion helps on topical queries.** BM25 + MiniLM is best there (+0.076 nDCG@10 over BM25, p = 0.0015), but on synopses it ranks the target first less often than BM25 alone (MRR@10 0.380 vs. 0.425).
- **Surface overlap beats meaning.** When the edited sentence keeps the original's words, every system prefers it (accuracy ≤ 0.24). With overlap controlled, the encoders catch most negation and number edits, but event order stays near chance. Direction edits are passed by word overlap alone (BM25 0.78).
- **E5 favours short texts, but that explains little of its gap.** Short units fill 17.5% of its topical top-10 but only 0.9% of the index; they are only slightly less relevant than its other hits, so they cost it about 0.01 P@10 of a 0.11 gap to MiniLM. Analyses: `python scripts/analysis.py results/milestone` → `results/milestone/analysis.json`.

Extended run ([results/extended/summary.md](results/extended/summary.md)): BGE-small, MPNet and E5-base don't close the gap on synopses (best dense MRR@10 is 0.287, against 0.458 for BM25 on whole reports). On topical queries MPNet and BGE are not significantly different from BM25. Keeping "not" in BM25 makes negation accuracy worse (0.08), because paraphrases express negation with other words.

### Larger encoders (`configs/large.yaml`)

Full tables: [results/large/summary.md](results/large/summary.md). Two size ladders (33M → 110M → 335M) and Qwen3-Embedding-0.6B, an LLM-based embedder.

| System | Params | Synopsis MRR@10 | Topical nDCG@10 (silver) | Contrast, overlap-controlled |
|---|---|---|---|---|
| BM25 / BM25 whole report | – | 0.425 / **0.458** | 0.630 / 0.621 | 0.53 |
| BGE small / base / large | 33M / 110M / 335M | 0.287 / 0.308 / 0.336 | 0.610 / 0.583 / 0.623 | 0.85 / 0.82 / 0.88 |
| E5 small / base / large | 33M / 110M / 335M | 0.241 / 0.280 / 0.299 | 0.438 / 0.451 / 0.556 | 0.85 / 0.82 / **0.89** |
| Qwen3-0.6B, generic instruction | 596M | 0.371 | 0.746 | 0.86 |
| Qwen3-0.6B, aviation instruction | 596M | 0.303 | 0.728 | 0.86 |
| BM25 + Qwen3 generic (RRF) | – | 0.446 | 0.746 | – |

- **Size helps, but not enough on synopses.** Both ladders improve monotonically (small → large: BGE +0.049, E5 +0.058 MRR@10, p < 0.001), and Qwen3 is best (0.371), yet every encoder stays below BM25 (Qwen3 −0.054, p < 0.001). BM25 + Qwen3 is the first system to beat chunk BM25 on synopses (0.446 vs 0.425, p = 0.018); it ties BM25 on whole reports (0.458, p = 0.23) and finds more targets in its top 100 (R@100 0.805 vs 0.753).
- **On topical queries Qwen3 beats BM25** (0.746 vs 0.630 nDCG@10, p < 0.001), even though the silver labels partly come from synopsis keywords, which favours lexical matching. Size alone does not do this: BGE-large ties BM25 (p = 0.81). E5's topical weakness shrinks with size (0.438 → 0.556).
- **Our aviation-specific Qwen3 instruction hurt** synopsis retrieval against the model card's generic web-search one (0.303 vs 0.371, p < 0.001); topical was not significantly different.
- **Contrast:** the larger models resist word overlap better in the proposal's condition (BGE-large and Qwen3 0.35 vs ≤ 0.24 before; Qwen3 negation 0.80), but event order stays at chance (Qwen3 0.48 controlled).

Qwen3-4B/8B and whole-report Qwen3 (2048 tokens, no truncation) need a CUDA GPU: [configs/large_gpu.yaml](configs/large_gpu.yaml).

### Taxonomy graph (`scripts/taxonomy_graph.py`)

Does a knowledge graph over the ASRS anomaly codes help? Each report links to its analyst codes; a classifier links a synopsis query to codes; BM25's top 100 is reranked by how well each candidate's codes fit. With perfect query linking (oracle) synopsis MRR@10 would rise from 0.425 to 0.643 (whole reports: 0.458 → 0.680). With a real linker (TF-IDF + logistic regression on train-split synopses, exact code set right for 21% of queries) the gain is +0.010 (p = 0.013; whole reports +0.012, p = 0.002). The graph carries signal, but linking a query to it is the bottleneck. The topical track cannot test this, because its silver labels come from the same codes. Output: `results/taxonomy_graph.json`.

## Unified ASRS + NTSB explorer

The UI lives in `Jacob19999/triaggent_consulting`, under
`portfolio/asrs-precedent-graph/`. Corpus v2 is separate from the benchmark corpus and its
reported results. To export the combined catalogue once summaries and narrative embeddings
are cached:

```bash
.venv/bin/python scripts/export_precedent_graph_v2.py /path/to/staging-page --without-graph
```

`--without-graph` supports UI development before the separate LLM knowledge graph is ready.
The export includes searchable summaries, source-qualified IDs, original coded factors,
explicit synopsis provenance and a separate shortlist of six ASRS ↔ NTSB narrative neighbours.
Cross-source links use cosine similarity of mean Qwen3-Embedding-8B chunk vectors; they do not
establish that reports describe the same incident. The page aligns identical coded factor
labels within a category while retaining their ASRS/NTSB provenance.

The browser searches summaries and metadata by keyword; semantic report-to-report links are
precomputed. Live semantic query retrieval remains available through
`asrsbench search configs/corpus_v2.yaml hybrid-bm25-qwen3-8b "query text"` on the machine
holding the models and caches. No v1 evaluation files or reported metrics change.
